# Скорость и опыт использования: список улучшений

Документ для **DeInventory Pro** (панель `/panel/*`) и публичного магазина **ArmikTech** (`/`).

Составлен по текущему коду, не как общий чеклист. Цель: быстрее открывать сайт, быстрее работать со складом на телефоне и на десктопе, меньше ждать синхронизацию и фото.

Приоритет: **P0** = заметно сразу, относительно безопасно. **P1** = сильный эффект, чуть больше работы. **P2** = новые фишки и полировка.

---

## Что уже хорошо

Эти вещи не надо изобретать заново. Их стоит развивать.

- Ленивая загрузка почти всех страниц в `App.tsx` (`React.lazy`).
- Виртуализация таблицы склада (`@tanstack/react-virtual` в `InventoryList`).
- Сжатие фото перед Storage (`utils/imageCompress.ts`, до ~520 KB JPEG).
- Debounce облачной записи (`WRITE_DEBOUNCE_MS = 1000`, быстрый flush 400 ms).
- `requestIdleCallback` при записи в `localStorage`.
- Шардирование Firestore (`syncPack`), чтобы не упираться в лимит 1 MB на документ.
- Настройки грузятся отдельным чанком (`SettingsModalHost`).
- На витрине есть skeleton сетки, wishlist, recently viewed, share.

## Часть 1. Скорость сайта

### P0. Первый экран (LCP / TTI)

1. **Самохостить шрифты Outfit и JetBrains Mono**  
   Сейчас `index.html` тянет Google Fonts по сети. Это лишний round-trip и риск блокировки текста. Скачать woff2, подключить через `@font-face` с `font-display: swap`. На витрине и в панели шрифт появится сразу.

2. **Убрать мёртвый `importmap` из `index.html`**  
   В production Vite его не использует, но браузер всё равно парсит ссылки на `esm.sh` и SheetJS CDN. Это шум, путаница и потенциальные лишние запросы.

3. **Не грузить Google GSI на каждой странице**  
   `<script src="https://accounts.google.com/gsi/client">` стоит в `<head>` всегда, включая публичный магазин. Подключать только на экране входа / настроек аккаунта.

4. **Preconnect только к нужным origin**  
   Для магазина: Firebase Storage / Firestore. Для панели: то же плюс `firebasestorage.googleapis.com`. Не preconnect к Google Fonts, если шрифты уже локальные.

5. **Разделить бандл витрины и панели**  
   Посетитель `/` не должен качать `InventoryList` (~8.8k строк), eBay-импорт, Excel, 3D-печать. Сейчас маршруты lazy, но общий `App.tsx` всё равно поднимает облачный стейт, геймификацию, undo, бэкапы. Вынести storefront в отдельный entry (`storefront.tsx`) без панели.

6. **Убрать неиспользуемый `@imgly/background-removal`**  
   Пакет в `package.json` есть, импортов в коде нет. Это тяжёлая ML-библиотека. Если не планируется cutout, удалить. Если планируется, грузить только в модалке фото.

### P0. Фото: главный тормоз списка

7. **Не показывать 1920px JPEG в превью 48px**  
   `ItemThumbnail` берёт полный URL. Для списка генерировать thumbnail 128/256 px (второй файл в Storage или Firebase Image Transform / `?alt=media` + resize). Список склада и витрина станут заметно легче.

8. **`loading="lazy"` + `decoding="async"` + фиксированный размер**  
   В `ItemThumbnail` этого нет. Без ширины/высоты прыгает вёрстка (CLS). Без lazy браузер качает все фото видимого и соседнего экрана. На витрине `ResilientStoreImage` уже делает lazy. Панель должна так же.

9. **WebP/AVIF при загрузке, JPEG как fallback**  
   Сейчас всё жмётся в JPEG canvas. WebP на тех же 1280 px обычно на 25-40% легче. Для витрины это прямой LCP.

10. **Не класть data-URL фото в `localStorage`**  
    Offline-режим пишет сжатые data URL в JSON склада. Это раздувает гидрацию, блокирует main thread на `JSON.parse` и упирается в квоту ~5 MB. Фото только в IndexedDB / Storage. В документе предмета хранить URL.

11. **Прогресс и очередь загрузки фото**  
    Уже есть `onProgress` в `inventoryImageStorage`. Показать его в UI: «3 из 8», не блокировать форму целиком, давать «продолжить в фоне». Сейчас длинный импорт ощущается как зависание.

### P0. Склад: React и память

12. **Разрезать `InventoryList.tsx` (сейчас ~8800 строк)**  
    Один компонент тянет Sale/Trade/Gift/Invoice/AI/Excel/модалки. Любой клик и фильтр пересчитывает огромное дерево. Вынести: таблицу, мобильные карточки, тулбар фильтров, модалки (lazy), bulk bar. Это и скорость, и меньше багов.

13. **Виртуализация мобильных карточек**  
    На десктопе таблица виртуализирована. На телефоне `MobileStockCard` рендерит все видимые отфильтрованные строки. При 200+ позициях скролл тяжелый. Тот же `@tanstack/react-virtual` для списка карточек.

14. **Не поднимать весь склад в React state на каждой странице**  
    `App.tsx` держит `items[]` целиком и прокидывает в layout, поиск, геймификацию, квоты. Dashboard / 3D / Settings не должны подписаться на полный массив. Контекст с селекторами (Zustand) или разделение: «лёгкий индекс» (id, name, status, price, thumb) + детали по запросу.

15. **Перестать сериализовать весь склад в `localStorage` при каждом сохранении**  
    Даже с debounce `JSON.stringify` тысяч позиций с specs/photos тормозит ввод. IndexedDB + инкрементальные патчи (изменилась одна запись).

16. **Мемоизация строк**  
    `ItemThumbnail` с `useState` на ошибку картинки. `MobileStockCard` без `React.memo`. При фильтре/выборе перерисовывается весь список. Мемо по `item.id` + версии полей, которые реально рисуются.

### P1. Сеть и чанки JS

17. **Лениво грузить Recharts**  
    `Dashboard.tsx` импортирует `recharts` сразу, плюс отдельная аналитика тоже. Графики только внутри виджета, `import()` по факту открытия дашборда. Сейчас чанк `vendor-charts` качается зря.

18. **Лениво грузить `xlsx` / ExcelJS / html5-qrcode / heic2any**  
    `SheetsImport` тянет `xlsx` статически. Excel нужен только при импорте/экспорте Finanzamt. Сканер штрихкода только в панели добавления. HEIC уже динамический (`await import('heic2any')`) - так же сделать остальное.

19. **`manualChunks` не должен всегда тащить xlsx**  
    В `vite.config.ts` xlsx выделен в vendor-чанк. Если страница его не импортирует, Rollup может всё равно связать. Проверить `vite-bundle-visualizer` и грузить только из динамических import.

20. **Prefetch следующей страницы**  
    При наведении на Stock / Add / Dashboard (`<Link prefetch>` или `import()` в `onPointerEnter`). На телефоне prefetch после idle. Переход по нижнему меню станет почти мгновенным.

21. **Skeleton вместо спиннера при смене маршрута**  
    `Suspense` в `PanelLayout` показывает крутящийся `Loader2`. Для склада показывать каркас таблицы/карточек той же высоты. Ощущение скорости важнее, чем реальные 200 ms.

22. **Service Worker только для статики и превью фото**  
    В `index.html` написано, что PWA убрали «для стабильности Vercel SPA». Можно вернуть узкий SW: кэш `index.html` + JS чанки + thumbnail URL. Без кэша API и без агрессивного offline HTML, чтобы не ловить старый бандл.

23. **HTTP-кэш для Storage**  
    Проверить `Cache-Control` у Firebase Storage. Превью должны жить долго (`immutable` + hash в имени файла). Сейчас повторный заход в склад снова качает те же JPEG.

24. **Не читать все eBay-коллекции на старте панели**  
    `App.tsx` тянет order/purchase/listing index. Грузить индексы при первом заходе на eBay Orders / Store Pull, не на Dashboard.

### P1. Витрина ArmikTech

25. **Пагинация / infinite scroll каталога**  
    `sortedFiltered.map` рендерит все товары сразу. При росте витрины это убьёт INP. Показывать 24 карточки, догружать по скроллу. URL: `?page=` или cursor.

26. **Приоритет LCP-картинки героя**  
    Первая hero / первая карточка: `fetchpriority="high"`, остальные lazy. Сейчас все одинаковые.

27. **Не грузить панель на `/`**  
    Отдельный HTML entry для магазина: меньше JS, быстрее TTI у покупателя, лучше Core Web Vitals.

28. **OG-картинка и размер изображений в карточке**  
    Карточка товара должна запрашивать ~600 px по ширине, не оригинал 1920. `sizes="(max-width: 640px) 100vw, 33vw"`.

## Часть 2. Опыт использования панели

### P0. Повседневная работа со складом

29. **Командная палитра (Ctrl/Cmd+K)**  
    Сейчас есть только `/` (поиск), `n` (добавить), `g` (дашборд). Нужен Spotlight: найти товар, продать, открыть Dealwatch, настройки, eBay orders. Это главный ускоритель для десктопа.

30. **Глобальный поиск с нормальным лимитом**  
    `GlobalSearch` режет до 5 результатов. Для склада из сотен позиций это мало. 15-20, группы (Active / Sold / Purchases / Settings), подсветка совпадения, стрелки + Enter.

31. **Сохранённые виды склада**  
    Набор фильтров «купить сегодня», «без фото», «sale-ready», «зависли 30+ дней», «eBay без привязки заказа». Один тап вместо ручной сборки фильтров каждый раз. Хранить в `localStorage` / cloud settings.

32. **Последний экран при открытии**  
    Если вчера работали в Inventory, не кидать на Dashboard. `start_url` манифеста сейчас `./` (магазин). Для установленного PWA панели: `/panel/inventory` или last route.

33. **Нижнее меню телефона ближе к реальной работе**  
    Сейчас: Home, Stock, **3D**, Add, Settings. 3D-печать важна, но ежедневнее Sell today / Dealwatch / Inbox. Сделать 3D во «ещё», а в таббар: Stock, Add, Sell, Search, More.

34. **Быстрая продажа без тяжёлой модалки**  
    `SaleModal` тянет платформы, заказы, сплиты. Для типовой KA-продажи: цена, площадка, готово. Расширенные поля за вторым шагом. На телефоне это экономит 5-10 секунд на каждую сделку.

35. **Мультивыбор жестом на телефоне**  
    Long-press -> режим выбора, свайп по чекбоксу. Bulk bar уже есть. Не хватает жеста, чтобы не целиться в маленький квадрат.

### P1. Клавиатура, фокус, «не терять место»

36. **Расширить шорткаты**  
    `s` продать выбранное, `e` редактировать, `p` фото, `Esc` закрыть модалку (уже частично), `j/k` по строкам, `?` шпаргалка. Сейчас `n` срабатывает и когда не ждали.

37. **Не сбрасывать скролл и фильтры**  
    После продажи/редактирования возвращать к той же строке (`highlightedItemId` уже есть). Сохранять search query, pin категории, сортировку в URL (`?q=&status=&cat=`). Можно шарить вид и не терять его при Back.

38. **Undo заметнее**  
    `UndoToastBar` есть. На телефоне его легко пропустить. Крупнее, с названием товара: «Sold RTX 3080. Undo 8s».

39. **Статус синка не перекрывает склад**  
    На мобилке бейдж синка `fixed top-right`. Не должен закрывать поиск. Иконка в таббаре / в шапке склада достаточна.

40. **Очередь офлайна**  
    Если сеть пропала, показывать «сохранено на устройстве, отправится когда будет сеть», не красную ошибку. Firestore persistence уже включён. Нужен понятный UX, не только `QuotaMonitor`.

### P1. Добавление товара и фото

41. **Черновик формы автосейв**  
    `ItemForm` длинный. Уход на камеру телефона не должен терять заполненные поля. IndexedDB draft по `itemId` / session.

42. **QR-загрузка фото уже есть. Сделать её первым шагом на телефоне**  
    В Add flow явно: «сфоткай здесь» или «открой QR на компьютере». Сейчас это панель внутри формы, её можно не заметить.

43. **HEIC с понятной ошибкой и превью сразу**  
    Конвертация уже есть. Показывать превью blob, пока идёт compress+upload. Не пустой слот на 3 секунды.

44. **Вставка скрина / DnD в любую точку формы**  
    Paste из буфера (Ctrl+V) в карточку товара. Сейчас загрузка через file input / отдельные панели.

45. **Один экран «этот лот готов к выставлению»**  
    Чеклист (`ListingPrepChecklistBar`) уже считает фото, OVP, specs. Сделать отдельный режим: только товары, которым не хватает одного шага, с кнопкой «доделать».

### P2. Новые фишки панели, которые экономят время

46. **Умный поиск опечаток**  
    `matchesInventorySearch` это AND по подстроке. «3080ti» не найдёт «3080 Ti». Лёгкий fuzzy (MiniSearch) по name/sku/specs.

47. **Недавние товары в поиске до ввода**  
    `getRecentItemIds` уже есть. Показывать их в пустом Global Search: «продолжить с…».

48. **Шаблоны листинга одним тапом**  
    Скопировать заголовок + описание + цену под KA / eBay. Listing Studio есть. Нужна кнопка «Copy KA block» прямо в строке склада.

49. **Массовая смена цены ±% / «округлить до 9»**  
    Для распродажи выходного дня. Bulk bar уже умеет многое. Не хватает ценового пресета.

50. **Напоминание «это, кажется, продано»**  
    `isMaybeSoldCandidate` и Sell Today уже подсказывают. Вынести бейдж на карточку склада и push/badge на иконке PWA.

51. **Сравнение двух карточек**  
    Для Dealwatch/склада: два товара рядом (цена покупки, sold comps, fees). Кусок compare UI в `public/dealwatch/compare.html` можно приземлить в панель.

52. **Тёмная тема панели**  
    Витрина умеет dark. Панель всегда slate-50. Ночные сессии на телефоне. Токены CSS, не invert.

53. **Пинч-зум**  
    В `index.html` стоит `user-scalable=no`. Это бьёт по доступности и мешает рассмотреть фото. Убрать. Защиту от accidental zoom сделать только на конкретных жестах списка, если реально мешает.

54. **Экран «что делать сегодня» как стартовый**  
    Sell Today + stale deals + sale-ready без фото. Один скролл вместо Dashboard с графиками. Графики оставить, но не первым экраном на телефоне.

## Часть 4. Надёжность, доступность, «ощущение готового продукта»

63. **Каркас ошибок вместо белого экрана**  
    Error boundary есть, но текст на английском и предлагает сброс cloud settings. Для панели: «Обновить», «Скачать локальный бэкап», без confirm(). Для витрины: мягкая страница без внутренних деталей.

64. **Focus trap и Esc во всех модалках**  
    Продажа, трейд, настройки, AI. Сейчас часть на `createPortal` без ловушки фокуса.

65. **Видимый focus ring**  
    Клавиатурный пользователь должен видеть, где курсор. Сейчас часть кнопок без `:focus-visible`.

66. **`prefers-reduced-motion`**  
    Геймификация, pulse-бейджи, спиннеры синка. Уважать системную настройку.

67. **Skip to content**  
    Для панели: пропуск сайдбара. Для витрины: к каталогу.

68. **Не блокировать scroll chaining аккуратно**  
    `overflow: hidden` на html/body в панели нужен, но на iOS иногда ломает клавиатуру и rubber-band. Проверить `100dvh` и visualViewport при открытой клавиатуре поиска.

69. **Локализованные пустые состояния**  
    «No matches found» в складе при DE-интерфейсе. Все empty/error на текущей locale.

70. **Индикатор «фото ещё грузятся» на карточке**  
    Серый плейсхолдер того же aspect-ratio, не иконка категории, которая потом прыгает в фото.

## Как мерить, что стало лучше

Не «кажется шустрее», а цифры.

| Метрика | Где | Цель |
|---|---|---|
| LCP | `/` витрина, мобильный 4G | < 2.5 s |
| INP | склад, фильтр + скролл | < 200 ms |
| CLS | список с фото | < 0.1 |
| JS transferred | `/` без логина | сильно меньше панели (ориентир: отдельный entry) |
| Time to first row | `/panel/inventory` после логина | строки на экране до конца облачного hydrate |
| Размер превью | Network, img склада | десятки KB, не 400-500 KB |

Инструменты: Lighthouse на `/`, Performance panel на складе с 300+ items, `npx vite-bundle-visualizer` на `npm run build`.

## Что сознательно не предлагается

- Переписывать React на другой фреймворк.
- Тащить GSAP / тяжёлый motion на склад. Склад должен быть «тупой и быстрый».
- Полноценный native app. PWA + быстрый web дешевле и покрывает телефон.
- Фоновый cutout (`@imgly/background-removal`) до тех пор, пока нет отдельного экрана и web worker. Иначе это удар по TTI.

1. Локальные шрифты + выкинуть лишние скрипты из `index.html`.
2. Thumbnail 256 px, не оригинал в списке.
3. Lazy + размеры на всех `<img>` панели.
4. Отдельный JS для витрины.
5. Распилить `InventoryList`.
6. Виртуализация мобильного склада.
7. IndexedDB вместо огромного `localStorage`.
8. Ctrl+K командная палитра.
9. Сохранённые фильтры + URL.
10. Быстрая продажа на телефоне и нормальный tab bar.
