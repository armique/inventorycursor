# Промпт для Claude Code: AI Attribution, Audit Trail & Unified Pending Inbox

Скопируй всё ниже и вставь в Claude Code внутри репозитория DeInventory (armiktech.com/panel).

---

## Контекст

Ассистент (Claude, через браузерную автоматизацию) будет вносить и изменять записи в этом инвентарном приложении: добавлять купленные товары, отмечать проданные товары, заполнять данные покупателя/продавца. Пользователь пока не полностью доверяет автоматическим правкам и хочет:

1. Чётко отличать, какие записи/поля тронул ассистент, а не пользователь вручную.
2. Видеть историю всех действий ассистента в одном месте, с возможностью перейти к товару.
3. Иметь возможность одним кликом **подтвердить** или **откатить (revert)** любое действие ассистента.
4. Объединить текущую вкладку "Purchases" (сейчас — только очередь распарсенных eBay-заказов, ожидающих подтверждения) в универсальный **инбокс pending-транзакций**, который отслеживает сделки с eBay И Kleinanzeigen, и покупки, и продажи, до их логического завершения — а затем автоматически маршрутизирует их в Active Inventory (для покупок) или Sold (для продаж).
5. Корректно моделировать разницу между:
   - **Kleinanzeigen Direkt Kaufen** — сделка не финализирована, пока покупатель/продавец не нажал подтверждение получения товара (после чего у продавца происходит выплата).
   - **Kleinanzeigen Cash / PayPal / Wire Transfer** — обычно считается завершённой сразу после оплаты/передачи, но должна давать пользователю мягкое ручное напоминание/тумблер "товар физически в наличии/получен", а не жёсткий блок.

## Задача 1 — Модель данных: атрибуция и аудит-лог

Добавь на все записи инвентаря (items, bundles, pending transactions):

```
source: "manual" | "ai"
lastModifiedBy: "manual" | "ai"
aiReviewStatus: "unreviewed" | "approved" | "reverted" | null   // null если запись никогда не трогал AI
```

Создай отдельную таблицу/коллекцию **`ai_actions`** (или `activity_log` с `actor` полем, если проще встроить в существующий лог):

```
id
timestamp
actor: "ai"
actionType: "item_created" | "item_updated" | "marked_sold" | "marked_received" | "buyer_info_filled" | "field_changed" | ...
itemId (ссылка на затронутый товар/бандл/pending-транзакцию)
diff: { field: string, oldValue: any, newValue: any }[]   // полный до/после снапшот изменённых полей
reviewStatus: "unreviewed" | "approved" | "reverted"
reversible: boolean   // false для необратимых действий (например, если письмо уже отправлено), true в большинстве случаев
sourceContext: string  // короткое пояснение, откуда взяты данные, напр. "Kleinanzeigen chat with Felix matthes, 23.07.2026"
```

Каждое AI-действие должно писать запись в `ai_actions` **и** обновлять `source`/`lastModifiedBy`/`aiReviewStatus` на самом товаре в одной транзакции.

## Задача 2 — Визуальная маркировка AI-действий

Везде, где товар/строка таблицы отображается (Inventory list, Sold, Purchases/Inbox, item detail):

- Небольшой **фиолетовый бейдж "AI"** рядом с названием товара, если `source === "ai"` или есть непросмотренные записи в `ai_actions` для этого товара.
- **Тонкая цветная полоса слева от строки** (4px, фиолетовая/индиго) для строк с `aiReviewStatus === "unreviewed"`. Полоса исчезает (или становится серой/приглушённой), когда пользователь нажимает "Approve" — но бейдж "AI" остаётся навсегда как метка происхождения.
- **Счётчик-уведомление** в боковой навигации рядом с новым пунктом меню (см. Задачу 3), показывающий число `unreviewed` действий.
- Добавь фильтр **"Source: AI"** в существующую панель фильтров (рядом с Platform/Payment), чтобы можно было мгновенно выбрать только AI-записи.

## Задача 3 — Новый раздел "Done by AI"

Создай новый пункт навигации **"Done by AI"** (иконка — робот/звёздочка) со страницей в виде хронологической ленты:

Для каждой записи из `ai_actions`, отсортированной от новых к старым:

- Timestamp, тип действия человекочитаемо ("Добавлен товар", "Отмечено как проданное", "Заполнены данные покупателя")
- Миниатюра/название товара — кликабельно, ведёт прямо на карточку товара (deep link, скроллит и подсвечивает нужную строку)
- Диф "было → стало" по каждому изменённому полю
- `sourceContext` — короткая цитата/пояснение, откуда взяты данные (например, из какого чата)
- Кнопки **Approve** и **Revert** прямо в ленте (без перехода на карточку)
- Массовое действие **"Approve all"** сверху ленты (для дня, когда пользователь будет полностью доверять)
- Фильтры: по типу действия, по диапазону дат, по статусу (unreviewed/approved/reverted)

**Revert** должен по возможности откатывать конкретно те поля, которые были изменены (используя `diff.oldValue`), а не удалять весь товар целиком, если товар после этого редактировался вручную — если после AI-действия было ручное изменение того же поля, `Revert` должен предупредить об конфликте, а не тихо перезаписать.

## Задача 4 — Объединённый Pending-инбокс (переименование "Purchases")

Переименуй текущую вкладку "Purchases" (сейчас — только eBay-парсинг заказов с Pending/Received/Ignored) в **"Pending" / "Inbox"** и расширь её логику, чтобы она отслеживала transactions обеих платформ и обоих направлений:

### Типы записей в инбоксе:

| Источник | Направление | Когда считается "pending" | Когда переходит в финал |
|---|---|---|---|
| eBay | Покупка | Заказ распознан/спаршен, не подтверждено получение | Пользователь жмёт "Получено" → уходит в Active Inventory |
| Kleinanzeigen Direkt Kaufen | Покупка | Оплачено, ждём подтверждения получения | Пользователь/статус чата показывает "Artikel erhalten" → Active Inventory |
| Kleinanzeigen Direkt Kaufen | Продажа | Оплачено покупателем, товар отправлен, ждём подтверждения покупателя и выплаты | Покупатель подтвердил получение (деньги выплачены продавцу) → Sold (финал) |
| Kleinanzeigen Cash/PayPal/Wire Transfer | Покупка или Продажа | Сразу помечается как "вероятно завершено", но с мягким статусом | Пользователь нажимает существующий тумблер "товар в наличии/получен" → финал. Если тумблер не нажат долго (например >3 дней) — можно показать мягкое напоминание, НЕ блокировать |

### UI:
- Табы/фильтры внутри инбокса: **Pending / Confirmed-not-final / Received/Finalized** (переименовать текущие Pending/Received/Ignored под новую логику, сохранив старую логику для eBay).
- Каждая карточка показывает: платформу, направление (покупка/продажа), контрагента, товар, сумму, способ оплаты, текущий статус сделки, и кнопку действия соответствующую этапу ("Confirm receipt", "Mark item in stock", "Ignore/Cancel").
- Если запись в инбокс добавлена AI (например, я нашёл сделку в переписке Kleinanzeigen и завёл её туда) — применяется вся маркировка из Задачи 2.
- При окончательном разрешении — автоматически создаётся/обновляется запись в Active Inventory или Sold, с переносом всех собранных полей (цена, доставка/кто платил, дата, имя контрагента, способ оплаты, платформа).

## Задача 5 — Не сломать существующий eBay-flow

- Существующая логика "Parse · Confirm · Ignore" для eBay-заказов должна продолжать работать без регрессий — она просто становится одним из "источников" внутри общего инбокса, а не отдельной изолированной вкладкой.
- Мигрируй существующие данные: у всех текущих записей в Purchases (2 pending eBay-заказа) должно сохраниться их состояние после рефакторинга.

## Приёмочные критерии

- [ ] Товар, добавленный вручную, не имеет бейджа AI и не появляется в "Done by AI".
- [ ] Товар/поле, изменённое мной (AI) через браузерную автоматизацию, получает бейдж AI + полосу + запись в логе с точным до/после.
- [ ] На странице "Done by AI" можно кликнуть на запись и перейти прямо на товар с подсветкой.
- [ ] Revert корректно откатывает конкретные поля, предупреждает при конфликте с более поздним ручным изменением.
- [ ] Вкладка "Pending/Inbox" показывает и eBay, и Kleinanzeigen сделки, обе покупки и продажи, с понятным статусом до финализации.
- [ ] Direkt Kaufen сделки не считаются "финал", пока не пройдёт соответствующее подтверждение (получение/выплата).
- [ ] Cash/PayPal/Wire Transfer сделки помечаются как "вероятно завершено" сразу, но остаются с мягким тумблером подтверждения, не блокирующим интерфейс.
- [ ] Существующий eBay parse/confirm/ignore флоу продолжает работать без регрессий.
