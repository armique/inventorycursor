# Промпт для Claude Code — Часть 2: Пруфы, ссылки на источник, напоминания

Продолжение первого промпта (`claude-code-prompt-ai-tracking.md`). Вставь в Claude Code после реализации Части 1 (модель данных source/ai_actions уже должна существовать) — эта часть на неё опирается.

---

## Контекст

Данные из этого приложения используются для отчётности в Finanzamt, поэтому для каждой купленной/проданной позиции критично иметь:
1. Точные структурированные данные (цена, доставка, дата, способ оплаты, контрагент).
2. **Прямую ссылку на первоисточник** — конкретный чат на Kleinanzeigen или заказ на eBay, чтобы одним кликом проверить статус ("получил ли я товар?") без ручного поиска.
3. **Визуальный пруф** (скриншот чата/оплаты/квитанции) как доказательство для налоговой, отдельно от самого чата (который может быть удалён/недоступен позже).
4. Автоматическое отслеживание "зависших" сделок (не финализированных дольше 3 дней), чтобы пользователь не забывал проверить статус.

## Задача 6 — Поля-ссылки на источник

Добавь на каждую запись (item / pending-transaction из Части 1):

```
sourceChatUrl: string | null       // прямая ссылка на переписку, напр.
                                    // https://www.kleinanzeigen.de/m-nachrichten.html?conversationId=XXXX
                                    // или https://www.ebay.de/mesg/ThreadView?... для eBay
sourceOrderUrl: string | null      // прямая ссылка на заказ/объявление, напр.
                                    // https://www.ebay.de/vod/FetchOrderDetails?itemId=...&transId=...
                                    // или ссылка на объявление Kleinanzeigen
counterpartyProfileUrl: string | null   // ссылка на профиль продавца/покупателя (eBay username page,
                                    // Kleinanzeigen "Alle Anzeigen von diesem Nutzer")
externalOrderId: string | null     // номер заказа eBay (#01-14946-82253) или ID переписки Kleinanzeigen
```

### UI:
- На карточке товара — три маленькие кликабельные иконки-ссылки рядом с именем контрагента: **"Chat ↗"**, **"Order ↗"**, **"Profile ↗"**. Показывать только те, что заполнены (не показывать пустую иконку).
- В таблице Inventory/Pending — компактная иконка-ссылка в столбце ACTIONS, открывающая `sourceChatUrl` в новой вкладке одним кликом (это то, ради чего всё затевается — "чтобы я мог перейти по ссылке и найти чат").
- Если запись создана мной (AI) — эти поля обязательны для заполнения при создании (валидация на бэкенде: если `source === "ai"` и `sourceChatUrl` пустой — блокировать сохранение и требовать заполнить, за исключением случаев, где сама платформа не даёт прямых URL, см. Задачу 7).

## Задача 7 — Пруф-вложения (скриншоты)

Добавь на каждую запись массив:

```
proofAttachments: [
  {
    id: string,
    type: "chat_screenshot" | "payment_confirmation" | "shipping_label" | "receipt" | "other",
    fileUrl: string,          // ссылка на загруженный файл (используй существующее файловое хранилище приложения)
    uploadedAt: timestamp,
    uploadedBy: "ai" | "manual",
    note: string | null       // напр. "Скриншот чата на момент подтверждения оплаты"
  }
]
```

### UI:
- Галерея миниатюр на карточке товара (как для фото самого товара, но отдельная секция "Proof / Nachweise").
- Кнопка "Add proof" — загрузка вручную (drag&drop или из буфера).
- Если запись создаёт AI — при наличии скриншота из браузерной сессии (Chrome-скриншот чата/подтверждения) AI обязан приложить его в `proofAttachments` с типом `chat_screenshot`, а не просто ссылаться на чат текстом.
- Экспорт для Finanzamt (существующий Excel/CSV экспорт, если такой есть, иначе — предложи Claude Code его добавить) должен включать ссылки на все `proofAttachments` каждой строки.

## Задача 8 — Отложенное раскрытие имени (Kleinanzeigen Direkt Kaufen)

Специфика: при продаже через Kleinanzeigen Direkt Kaufen реальное имя покупателя показывается в чате только **после покупки этикетки доставки (DHL/Hermes)** — до этого видно только псевдоним/инициалы.

Модель должна поддерживать создание записи ДО того, как известно полное имя:

```
counterpartyName: string            // может быть плейсхолдером, напр. "TBD — pending shipping label" или ник с чата
counterpartyNameConfirmed: boolean  // false, пока не появилось настоящее имя
```

### Логика:
- AI (или пользователь) может создать/обновить запись с `counterpartyNameConfirmed: false` и ником вместо имени — это не должно блокировать создание записи.
- Запись с `counterpartyNameConfirmed: false` попадает в отдельный фильтр/бейдж **"Имя не подтверждено"** в Pending-инбоксе (из Части 1, Задача 4), чтобы не потерять её из виду.
- Как только имя раскрывается (после покупки этикетки) — обновить `counterpartyName` и выставить `counterpartyNameConfirmed: true`. Это одно из действий, которое AI должен уметь выполнить при повторном сканировании того же чата (перечитать чат позже и обновить только имя, если оно появилось).
- **Обязательно всегда сохранять `sourceChatUrl`** для таких записей — это единственный способ вернуться и проверить, раскрылось ли имя, раз оно недоступно сразу.

## Задача 9 — Напоминания о зависших сделках (3+ дня)

Чисто серверная логика на существующих датах, ИИ здесь не требуется — обычный scheduled job (cron/Vercel Cron/Supabase Edge Function/что используется в стеке — Claude Code сам определит подходящий механизм по кодовой базе).

### Условия триггера (raз в день):
- **Покупка**, статус "оплачено/оплата ушла", но НЕ отмечена как полученная >= 3 дней с даты оплаты → уведомление: *"Проверь статус заказа от {counterpartyName} — оплачено {N} дней назад, товар ещё не получен"* + ссылка на `sourceChatUrl`.
- **Продажа через Direkt Kaufen**, товар отправлен, но покупатель не подтвердил получение (соответственно, выплата не пришла) >= 3 дней с даты отправки → уведомление: *"Покупатель {counterpartyName} не подтвердил получение {N} дней — возможно, стоит написать ему"* + ссылка на `sourceChatUrl`.
- **Любая транзакция** с `counterpartyNameConfirmed: false` дольше 3 дней → отдельное уведомление *"Имя покупателя всё ещё не раскрыто — проверь, куплена ли этикетка"*.

### UI:
- Badge-счётчик в навигации (можно объединить с "Done by AI" счётчиком или сделать отдельным — "⚠ N сделок требуют внимания").
- Список этих уведомлений — отдельная секция вверху Pending-инбокса (из Части 1), не отдельная страница, чтобы не плодить лишние разделы.
- Опционально: email/push уведомление, если в приложении уже есть система уведомлений — если нет, ограничиться in-app бейджем на первом этапе (не усложнять).

## Задача 10 — Не менять

- **Bulk Import** (текстовый/ручной ввод позиций бандла + общая цена → авто-разбивка по логике цен) уже работает как нужно — трогать не надо. AI будет использовать его как есть: если в объявлении бандла нет полного списка деталей, AI вписывает обобщённое название компонента (например "Grafikkarte" вместо конкретной модели), а пользователь позже уточняет вручную.

## Приёмочные критерии (дополнение к Части 1)

- [ ] У товара/pending-записи есть кликабельные ссылки на чат/заказ/профиль, если они были заполнены при создании.
- [ ] Запись, созданная AI, не проходит валидацию без `sourceChatUrl` (кроме документированных исключений).
- [ ] Можно прикрепить и посмотреть скриншот-пруф прямо на карточке товара.
- [ ] Запись можно создать с неподтверждённым именем контрагента и позже обновить его, не создавая дубликат.
- [ ] Ежедневная джоба присылает уведомление о сделках старше 3 дней без финализации, с прямой ссылкой на чат.
- [ ] Bulk Import и его логика разбивки цены не изменены и не сломаны.
